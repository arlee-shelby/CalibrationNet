# Repository layout

What lives where, and which script produces which files. Rule of thumb:
the repo root holds only the package, the pipeline's entry points, and
their documentation; everything generated lands in a dedicated output
directory; everything historical lands in `development/`.

## Directories

| directory | contents |
|---|---|
| `calibrationnet/` | the Python package: ORM models, pipeline modules, fit code (`fit_functions.py` — frozen physics; `fit_functions_reference.py` — the untouchable benchmark copy), fit recipes, geometry, positions, query helpers |
| `scripts/` | every pipeline entry point (see the table below) |
| `alembic/` | database migrations (`alembic upgrade head` applies them) |
| `data/` | canonical machine-readable inputs the seeds read (see the seed-file table below); `data/TrapFilterData/` is the cluster-side staging area for trap filter jobs (un-ingested CSVs + manifests + `slurmout/` logs — gitignored, transient) |
| `data/provenance/` | the human documents the seeded data came from: the Source Installation History PDF, the corrected 7/21 installation figure, and the pixel preamp/FET map figures from which `data/pixel_wiring.csv` was hand-transcribed |
| `docs/` | design & how-to documentation (this file, fit_storage.md, position_planning.md, pipeline_roadmap.md, example_outputs.md) and `docs/examples/` with committed example figures |
| `plans/` | current source-position plan deliverables (CSV + positions list + summary + coverage maps, per holder/convention/tag) — regenerated by scripts/optimal_positions.py |
| `fit_plots/` | QA figures from fitting/calibration `--plot` runs (gitignored, regenerable) |
| `hitmaps/` | hit maps from scripts/show_hitmap.py (gitignored, regenerable) |
| `development/` | development-era material, kept for reference, none of it needed to run the pipeline: `inputs/` (uploaded reference files: sample h5, nabPy CSV outputs, collaboration code, reference hit maps), `notebooks/` (exploration notebooks and the pre-pipeline fitting sketch), `outputs/` (superseded generated files: old-format position lists, the pre-envelope plan, review-CSV edits, run lists) |

Working files at the root: `source_assignment_review.csv` (the live
assignment review file, gitignored — assign_sources.py writes and reads
it in place).

## Seed files: what changes, and when

All seeds are idempotent (re-running is always safe), so the files stay
together in `data/` — but they mutate at very different rates:

| file | reseed when | expected frequency |
|---|---|---|
| `pixel_wiring.csv` | a preamp/FET remap (transcribed from the map figures in `data/provenance/`) | almost never |
| `Current CAL2702 Sources.xlsx` | a new physical source arrives | rare |
| `source_installations.csv` | every tray (re)installation | every installation |
| `decay_energies.csv` | new isotope lines, corrected keV values, intensities | occasionally (keV values append as new versions; intensities update in place) |

Board-channel maps are NOT seed data: they live in the raw .h5 files
and, once ingested, in `run_pixels.board_channel` — the transfer CSV
(`bc_maps*.csv`) is transient and gitignored; don't accumulate it.

## Which script makes what

| script | reads | writes |
|---|---|---|
| seed_pixels / seed_sources / seed_source_installations / seed_decay_energies | files in `data/` | pixels, sources, source_installations, isotope_decay_energies + kev_peaks tables |
| ingest_run.py | slow-controls DB (tunnel) + motion archive | runs + run_segments tables |
| submit_trap_filter.sh → apply_trap_filter.{sh,py} (cluster) | run .h5 files | trap_filter_outputs table (manifest + logs under `data/TrapFilterData/`) |
| ingest_filter_output.py | a filter-output CSV | trap_filter_outputs table |
| ingest_board_channels.py / extract_bc_maps.py | run .h5 / `data/bc_maps.csv` | run_pixels.board_channel |
| assign_sources.py | trap filter counts | `source_assignment_review.csv`; `--apply` writes run_pixels.source_id |
| optimal_positions.py | trap filter counts + installations | `plans/optimal_positions_plan_*` (CSV, positions CSV, summary txt, 2 coverage PNGs) |
| show_hitmap.py | trap filter counts | `hitmaps/Run*_hitmap.png` |
| fit_spectra.py | trap_filter_outputs | spectrum_fits table; `--plot` → `fit_plots/Run*_<fitlabel>.png` |
| extract_adc_peaks.py | spectrum_fits + decay lines | adc_peaks table |
| calibrate.py | adc_peaks + kev_peaks | calibrations + calibration_points tables; `--plot` → `fit_plots/Run*_calibration.png` |
| benchmark_fits.py | trap_filter_outputs | nothing (live-vs-reference fit comparison report) |
| process_run.py | — | runs every stage above for one run, in order, idempotently |
| pending_segments.py | database | manifest / progress report (stdout) |

## What must stay in sync

- Moving/renaming anything in `data/` requires updating the seed script
  defaults (they point at these paths).
- `calibrationnet/fit_functions_reference.py` must NEVER change
  (md5-pinned; scripts/benchmark_fits.py verifies).
- Table/column changes always go through an alembic migration.
